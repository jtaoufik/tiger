The API client that lives in your repo

A format you can read

One request per file. Open it in any editor, grep it, template it. Saving an unchanged request never produces a diff, so your history stays clean.

Prefix a line with ~ to disable it without deleting it. Environments are files too. 

meta {
  name: Create post
  seq: 2
}

post {
  url: {{baseUrl}}/posts
}

headers {
  Content-Type: application/json
  ~X-Debug: 1
}

body:json {
  { "title": "Hello from Tiger" }
}

Your AI assistant can drive it

Tiger ships a Model Context Protocol server. Point Claude (or any MCP client) at a collection and it can list requests, read them and run them, with environments resolved, and get structured responses back.

Debugging an API with an assistant stops being copy-paste archaeology.

{
  "mcpServers": {
    "tiger": {
      "command": "node",
      "args": [
        "tiger/out/mcp/server.mjs",
        "path/to/collection"
      ]
    }
  }
}

Questions, answered

Is Tiger really free?

Yes. Tiger is MIT licensed, free for personal and commercial use. There is no paid tier, no seat pricing and no feature gate.

Where is my data stored?

On your disk, in folders you choose. Tiger has no server and no account system. Anonymous usage analytics (never your URLs, headers or bodies) can be switched off in Settings.

Does it work on Windows?

Yes. Tiger builds for macOS, Windows and Linux from the same codebase, with installers for each.

Can I migrate from Postman?

Export your collection from Postman as v2.1 JSON and import it from the sidebar. Folders, headers, query params, bodies and variables carry over.
